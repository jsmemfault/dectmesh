Nordic Thingy:91 X · a proof of concept

The self-organizing mesh DECT NR+ is missing.

Nordic ships the DECT NR+ PHY — and, above it, a star. What's missing is an open, self-organizing, multi-hop mesh. Æther fills it on a Thingy:91 X: nodes find each other, form a routing tree, and carry real traffic across hops. And because every layer speaks 9P, the whole mesh behaves like one filesystem — so its capabilities compose instead of piling up. We'll climb the stack from the radio up, and finish by saving a file that reflashes a node across the air.

meet Æther

Æther is a mesh — built in layers, over the air.

Æther is a general-purpose mesh protocol, hand-built for LoRa radios and radio-agnostic by design — the PHY is a swappable bottom layer. Here it's ported to DECT NR+. Four layers turn a bare radio into a self-organizing network: Nordic gives you the bottom one, Æther is everything above it — and at each layer, 9P turns hidden machinery into something you can read, write, and compose.

L4 · services

What you actually do

Chat, live telemetry to the cloud, remote browsing, firmware updates — every feature the mesh offers.

9Pthere's no app protocol. Each feature is a file you read or write — so new capabilities cost nothing to add.
L3 · HONR routing

Finding the way, on its own

Nodes elect a root and self-organize into a tree, each earning a routing address (HONR) that encodes its place in it — so forwarding is stateless, the next hop computed from the address alone, no route tables. Messages hop node-to-node; the tree re-forms when the topology changes. No coordinator, no config.

9Pthe routing tree isn't hidden state — it's files (dev/aether/tree, rank, parent). You debug the mesh through the same interface.
L2 · HeyMac

Talking reliably on a half-duplex radio

Framing, reliable unicast (a stop-and-wait ARQ that retransmits until the peer acknowledges), and broadcast for discovery — plus a self-certifying identity per node: a CGA, the SHA-256 of the node's own public key, stable for its whole life.

9Pone datagram carries one 9P message. This ARQ is the transport whole filesystem sessions ride on.
L1 · DECT NR+ PHY

The airwaves

Nordic's DECT NR+ PHY firmware on the nRF9151 — which, in Nordic's own words, “implements only the physical layer.” DECT NR+ is DECT-2020 New Radio (ETSI TS 103 636), a non-cellular 5G (IMT-2020) standard on license-exempt, regulated channels — here ~915 MHz.

↑this is the piece Nordic ships. Its stack above the PHY targets a star topology — a self-organizing, multi-hop mesh is exactly the gap Æther fills.
self-organizing · stateless multi-hop routing
Each address encodes the node's path from the root (HONR), so every node forwards by math alone — no route tables, no discovery. A message to 12:00 hops root → 10:00 → 12:00; the ACK returns the same way. And because these addresses shift as the tree heals, every node also carries a durable, key-bound identity (CGA) — you address who a node is, and the mesh finds where it is.
the connective tissue — a 40-year-old idea

Where “9P” comes from — and why it multiplies everything.

We keep invoking 9P. It isn't ours, and it isn't new. The people who built Unix built Plan 9 to finish the thought: make everything a file — every device, every service, even a machine across the network — and address all of it with one small protocol, 9P. Then Inferno carried it into embedded devices, where a sensor across the world was just a file you mounted. Æther brings that same idea to a radio mesh.

remote presence, put to work

Reach across the mesh — then read out, or write in.

Once you can mount a node over the air, you operate it as if you were sitting at it. And since everything it does is a file, there are only two moves: read its state out to the cloud, or write new state in. Observability and firmware updates turn out to be the same primitive, run in opposite directions.

Mount a node three hops away and inquire about it as if you were sitting at it — its sensors, its vitals, its routing state. Remote access, an old networking book quipped, is a lot like astral projection; 9P makes the whole mesh feel that way. Below: the two things you do once you're “there.”

Telemetry out to the cloud

Read a remote node's sensor and system telemetry — environment, device vitals, radio health, even a crash coredump — straight over the mesh. At the mesh's edge, a forwarder drains it and ships it to nRF Cloud. Nodes with no internet of their own still get observed.

Firmware in to the silicon

The very same mount, written. Send a signed image to the node's firmware slot and it validates and reflashes — entirely over the air, no wire to the target. The node is named by its durable identity, so the image lands wherever the tree has moved it. Proven 15/15 on the bench.

trust, without infrastructure

Even authentication is a file.

9P has always proven identity through a file — the auth handle opened by its Tauth handshake. Æther makes that proof self-certifying: a node's name is the hash of its public key, so it proves who it is with no certificate authority, no pre-shared keys, no key server — nothing to distribute or revoke.

verify a node — write a challenge, read a proof

You prove who a node is, independent of where it is (HONR) — so identity and its proof stay invariant as the node roams and the tree heals. Exactly the trust model an unattended metering or industrial fleet needs.

Nodes find each other

Drop nodes anywhere and they discover neighbors, elect a root, and self-organize into a tree — no coordinator, no site survey, no configuration. The network assembles itself.

They route across hops, reliably

Traffic hops node-to-node, so the network reaches nodes no single radio could — coverage without wiring, the whole point of a mesh. A stop-and-wait ARQ retransmits until acknowledged; proven 10/10 both directions over a 2-hop path, and the tree re-forms when a node moves.

They carry real traffic — in both directions

Sensor and system telemetry drained out to nRF Cloud through a forwarder at the mesh edge; firmware and config written back in. The observability and OTA flows above are the read and write halves of this.

it's all files: net/aether/chat, dev/mflt_mesh, dev/firmware

Remote management, for free

Mount a node three hops away and operate it as if it were local — inspect its state, reconfigure it, pull diagnostics — with zero mesh code on the client. (This is the astral projection above.) The mesh carries sessions, not just packets.

a real 9P session — version · attach · walk · open · read — over multi-hop unicast

🍒 And the cherry: fleet firmware updates, over the air

The operational necessity for any real deployment. Because an update is just a file write that resolves across the mesh, OTA to a node with no wire needed no new protocol — only a client that writes the peer's dev/firmware, named by its durable identity and delivered wherever the tree has since moved it. We ran it into the ground to be sure.

15 / 15 full 305 KB images, zero failures ~56 s each, MCUboot-validated 1 interrupted & resumed → still valid

Honest scope: the mesh results are on a small bench — OTA is single-hop, one RF environment, N = 15; multi-hop-through-a-relay OTA and long-run endurance are named, not yet claimed. The CGA ownership proof is implemented and validated (spoofed and replayed proofs are both rejected); gating every mesh session on it through 9P's Tauth is designed, not yet wired. But the shape is real: a self-organizing DECT NR+ mesh where 9P makes every capability — down to authentication — compose.
